# Edward 个人成长成功系统 — 产品架构文档

> **版本**: v2.0 | **日期**: 2026-10-13 | **作者**: Edward × AI Co-Pilot  
> **定位**: 面向高净值个人成长者的 AI 驱动全维度成长平台  
> **文档用途**: 多模型专家交叉验证 — 产品架构、技术选型、用户体验、商业化路径

## 一、产品愿景与核心理念

### 1.1 愿景

> **让每一个追求卓越的人，都能在 AI 的陪伴下，系统性地成长为自己理想中的样子。**

Edward 个人成长成功系统（以下简称"成长系统"）是一款以 **认知科学 + 游戏化 + AI 智能** 为三引擎的个人全维度成长平台。它不是传统的 TODO 应用或知识管理工具，而是一套融合了：

- **艾宾浩斯遗忘曲线**的间隔复习系统
- **国际级游戏数值策划**的激励体系
- **即时专家**的 AI 实时知识赋能
- **MASK 四维能力模型**（Mindset / Attitude / Skills / Knowledge）
- **马斯洛需求层次**的自我实现追踪
- **国学经典**的东方智慧修炼

的成长操作系统。

### 1.2 核心设计原则

| 原则 | 说明 |
|------|------|
| **Apple 级极简** | 干净克制，信息密度高但不杂乱，每个界面只聚焦一件事 |
| **科技酷炫感** | 暗色侧边栏、毛玻璃效果、渐变光效、3D 翻转卡片 |
| **寓教于乐** | 打怪升级式成长，20 级成长体系、23 种成就徽章、每日任务 |
| **即时价值** | 50-100 秒内获得一个可直接使用的专家级解读 |
| **科学驱动** | SM-2 间隔重复算法、艾宾浩斯遗忘曲线、SMART 目标框架 |
| **通用可复制** | 不绑定特定行业，任何人都可以使用这套系统成长 |

### 1.3 目标用户画像

| 维度 | 描述 |
|------|------|
| **核心用户** | 25-45 岁，企业高管/创业者/专业人士，追求持续成长 |
| **核心痛点** | 知识碎片化、学了就忘、缺乏系统成长路径、社交场合知识盲区 |
| **使用场景** | 晨间规划 → 通勤学习 → 社交即时查词 → 午间签到 → 间隔复习 → 晚间反思 |
| **付费意愿** | 中高，愿意为高质量 AI 服务和个性化体验付费 |

### 2.1 八大核心功能模块

#### 模块 1：即时专家（Instant Expert）⭐ 高频核心功能

**场景**：社交/商务/新闻中遇到陌生词汇，50 秒内获得可朗读的专家级解读。

| 维度 | 说明 |
|------|------|
| **输入** | 关键词 + 可选场景描述 |
| **输出** | 50-100 字专业解读，一段话，可直接朗读 |
| **AI 模型** | Kimi kimi-k2.6（推理模型，免费额度） |
| **System Prompt** | 自信专业语气、先本质后案例、用数字增强说服力、像即兴发言 |
| **触发方式** | Web 前端输入 / 飞书机器人发送"专家 + 关键词" |
| **知识沉淀** | 自动保存到 knowledge_insights 表，可后续复习 |

**技术流程**：
```
用户输入关键词 → POST /api/v1/expert/ → AIService.chat()
  → Kimi API (kimi-k2.6, max_tokens=2000)
  → 解析 content（若空则取 reasoning_content）
  → 保存到 knowledge_insights
  → 返回解读 + 时间戳
```

#### 模块 2：游戏化成长中心（Gamification）

**设计理念**：参考国际 3A 级游戏数值策划，让用户在"不知不觉"中持续成长。

**等级系统（20 级）**：

| 等级 | 称号 | 升级所需 XP | 累计 XP |
|------|------|------------|---------|
| 1 | 成长新手 | 100 | 0 |
| 2 | 求知者 | 150 | 100 |
| 3 | 学徒 | 225 | 250 |
| 4 | 探索者 | 338 | 475 |
| 5 | 实践者 | 506 | 813 |
| 6 | 精进者 | 759 | 1,319 |
| 7 | 专精者 | 1,139 | 2,078 |
| 8 | 智者 | 1,709 | 3,217 |
| 9 | 觉者 | 2,563 | 4,926 |
| 10 | 大师 | 3,845 | 7,489 |
| 11-20 | 宗师 → 传奇 → 人生赢家 | ... | ... |

> **XP 公式**: `XP(L) = 100 × 1.5^(L-1)`，指数增长确保后期升级有成就感。

**成就系统（23 种徽章，6 大类别）**：

| 类别 | 成就示例 | 解锁条件 |
|------|---------|---------|
| 🧠 学习 | 初识知识、学无止境、知识海洋 | 学习 1/10/50 个内容 |
| 🔄 复习 | 温故知新、记忆大师、不忘初心 | 复习 1/10/50 次 |
| 🔥 习惯 | 三日筑基、七日成习、月度达人 | 连续签到 3/7/30 天 |
| 🌟 特殊 | 破晓之星、夜猫子、全勤战士 | 特定时间签到 |
| 🤝 社交 | 分享达人、知识传播者、邀请之王 | 分享/邀请达标 |
| 📊 维度 | 全面发展、六边形战士 | 覆盖 N 个学习维度 |

**每日任务系统**：
- **主线任务**（4 种模板）：学习 N 个内容、完成签到、复习 N 张卡片
- **支线任务**（4 种模板）：记录知识应用、阅读国学、练习演讲
- **挑战任务**（3 种模板）：连续复习 N 天、探索新维度、社交分享

**连续打卡（Streak）**：
- 按活动类型独立追踪（签到/学习/复习/演讲）
- 冻结令牌：可消耗令牌保护连续记录不因一天中断而清零
- 每日 0 点自动检查

#### 模块 3：间隔复习系统（Ebbinghaus / SM-2）

**算法核心**：SM-2 间隔重复算法

```
输入：ease_factor（默认 2.5）、interval、quality（0-5 评分）、review_count

若 quality < 3（忘了）：
  → ease_factor = max(1.3, ease_factor - 0.2)
  → interval = 1（明天重新来）

若 quality >= 3：
  → ease_factor = ease_factor + (0.1 - (5-quality) × (0.08 + (5-quality) × 0.02))
  → ease_factor = max(1.3, ease_factor)
  → interval 递进：1 → 2 → round(interval × ease_factor)
```

**评分体系**：
| 按钮 | 含义 | quality 值 | 效果 |
|------|------|-----------|------|
| 忘了 | 完全忘记 | 1 | 重置间隔，降低难度因子 |
| 有点印象 | 模糊记得 | 3 | 短间隔复习 |
| 轻松记住 | 牢固掌握 | 5 | 长间隔推进 |

**卡片来源**：
1. 手动创建
2. 从结构化知识自动生成（`POST /cards/generate-from-knowledge`）
3. 复习完成后自动安排下次复习日期

**数据统计**：到期卡片数、总卡片数、正确率、连续复习天数

**内容属性**：

#### 模块 5：知识管理全链路

```
知识捕获 → NLP 处理 → 结构化 → 知识图谱 → 应用追踪 → 演讲素材
   │           │          │          │           │          │
   │    意图分类     核心概念     节点+边      场景记录    模板生成
   │    领域识别     示例应用     掌握度       效果评分    双语版本
   │    实体提取     难度/重要度   中心性       跟进标记
   │    标签生成
   ▼
KnowledgeInsight → StructuredKnowledge → KnowledgeGraph → Application → SpeechDraft
```

**知识状态流转**：`raw → structured → crystallized → shared`

**知识图谱**：
- 节点（Concept）：领域、概念名、掌握度、中心性得分
- 边（Edge）：关系类型、强度、是否双向
- 支持从结构化知识自动生成节点和边

#### 模块 6：目标与习惯

**SMART 目标框架**：
- Specific / Measurable / Achievable / Relevant / Time-bound
- 优先级（高/中/低）、分类、进度百分比
- 100% 自动完成

**习惯追踪**：
- 频率（每日/每周）、目标值
- 连续打卡天数、最长连续
- 习惯完成日志

| **数据库** | PostgreSQL 16 | JSONB 支持、UUID 主键、全文索引 |
| **缓存** | Redis 5 | 爬虫去重、会话缓存 |
| **AI 服务** | Kimi kimi-k2.6 | OpenAI 兼容协议、推理模型 |
| **ORM** | SQLAlchemy 2.0 | 声明式模型、异步会话 |
| **认证** | JWT (HS256) | Access Token 24h + Refresh Token 7d |
| **定时任务** | APScheduler | AsyncIOScheduler、CronTrigger |
| **部署** | 本地 Docker | PostgreSQL + Redis + Backend + Frontend |

### 4.2 核心模型字段说明

**UserProfile（用户画像）** — 最丰富的单表，承载多维评估数据：

| 字段组 | 类型 | 说明 |

| `streak_days` / `longest_streak` / `freeze_tokens` | Int | 连续打卡数据 |

### 6.2 AI 使用场景

| 场景 | System Prompt 要点 | 输出格式 |
|------|-------------------|---------|

| **NLP 意图分类** | 规则引擎（非 LLM），7 种意图 | 意图 + 领域 + 实体 + 标签 |

### 6.3 容错设计

```python
# 1. API Key 未配置 → 返回友好提示
if not self.api_key:
    return "AI服务暂未配置..."

# 2. 推理模型 content 为空 → 取 reasoning_content 作为降级
content = msg.get("content", "").strip()
if not content and msg.get("reasoning_content"):
    content = msg["reasoning_content"].strip()

# 3. HTTP 错误 → 记录响应体便于调试
except httpx.HTTPStatusError as e:
    body = e.response.text[:200]
    print(f"AI service error: {e} | body: {body}")

# 4. 所有异常 → 统一降级到 fallback
except Exception as e:
    return self._fallback_response(prompt)
```
